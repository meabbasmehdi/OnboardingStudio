# Contributing

## Development Workflow

1. Build the package before opening a pull request.
2. Add or update tests for any behavior change in paging, controls, motion, or spotlight sequencing.
3. Keep public APIs documented with concise comments.
4. Prefer theme-driven customization over one-off view flags when extending the UI.

## Code Style

- Keep the library modular and composable.
- Default to SwiftUI-native solutions.
- Avoid third-party runtime dependencies.
- Keep the premium visual language consistent across templates and examples.

## Pull Requests

- Include a short summary of the change.
- Include screenshots or screen recordings for visual changes.
- Mention any public API additions or migrations in `CHANGELOG.md`.
